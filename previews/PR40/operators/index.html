Building operators

This page is the guide to the operator interface: how to get a Hamiltonian into OpSum, and the patterns that keep it correct. The example pages — starting with Spin chains — work the same material through concrete models; Reference lists every docstring.

The shape of the pipeline

TensorMap ──project(O, B)──► SiteOperator / LocalOperator ──A[i], B[i, j]──► Terms ──opsum(lat, …)──► OperatorSum ──mpo──► SymbolicMPO
spin_ops, fermion_ops, … ───┘

A site is an operator Basis: an ordered list of operators on the physical space, the identity first, in which every on-site operator is expanded. For the common sites there is a stock basis and a builder that hands out the operators already expanded in it; for anything else you write a TensorMap and project it.

A bag of terms is latticeless: nothing in the term algebra needs a physical site, and the compression itself needs only the number of sites. The lattice enters when the terms are added to an OperatorSum, which is the one container that holds a lattice (one basis per site), the terms placed on it, and any exponentially decaying channels — and the one thing mpo, instantiate and islossless take. Six types carry the whole interface:

TypeWhat it isHow you get one
SiteOperatoran operator on one site, not yet placeda single-site entry of a builder (spin_ops(U1Irrep).S_z), project(O, B), scalarop
LocalOperatoran operator on K slots, not yet placeda two-site entry of a builder (spin_ops(SU2Irrep).S_exchange), project(h, B)
Termsthe compressible operator: a bag of Terms, no latticeA[i], B[i] / B[i, j], * of placed operators, opsum, +, append!, copy, zero, one; the low-level couple
FiniteChain / InfiniteChainthe lattice: one basis per siteFiniteChain(B, N), FiniteChain([B₁, B₂, …]), InfiniteChain(B), InfiniteChain([B₁, B₂])
OperatorSuma lattice plus the terms (and channels) on it; letters are checked against the bases as they enteropsum(lat, terms...), OperatorSum(lat) + opsum!, +, *, H'
SymbolicMPOthe compressed MPO, on either lattice; with MPSKit loaded instantiate(W) is MPSKit's Hamiltonianmpo

Everything named here is exported, so using OpSum is enough. The exception is dot (the Cartesian Sᵢ·Sⱼ), which is LinearAlgebra.dot and needs using LinearAlgebra: dot.

Never name an alphabet letter by its index

Behind every operator is a set of letters IrrepOperator{I}(c, n): an operator charge c and an index n, the n-th element of charge c in the site's basis. A basis shows what it holds:

using OpSum, TensorKit

spin_basis(U1Irrep)
Basis(Rep[U₁](1/2 => 1, -1/2 => 1); 4 elements: Irrep[U₁](0) => 2, Irrep[U₁](1) => 1, Irrep[U₁](-1) => 1)

Four elements: the identity and Sᶻ (both of charge 0), and the two charged ones S⁺ and S⁻. Which element is which depends on the order the basis was built in, so do not write those ns into your code: reorder the definition and every letter index permutes silently, giving a different Hamiltonian and no error. Write the operator down instead (a builder entry or project), and let OpSum find the letters.

On-site operators

Stock bases and builders

Each common site has a basis, spin_basis, fermion_basis, boson_basis, hubbard_basis and tj_basis, taking the symmetry as an argument, and a builder of the same stem (spin_ops, fermion_ops, boson_ops, hubbard_ops, tj_ops). The builder returns a NamedTuple of every charge-neutral operator of that site that the symmetry admits, expanded in the basis and named after the functions of TensorKitTensors.jl:

B = spin_basis(U1Irrep)
ops = spin_ops(U1Irrep)
keys(ops)
(:S_z, :S_z_S_z, :S_plus_S_min, :S_min_S_plus, :S_exchange)

A single-site entry is a SiteOperator (ops.S_z), placed with ops.S_z[i]; a two-site entry is an unplaced LocalOperator (ops.S_plus_S_min), placed with ops.S_plus_S_min[i, j]. The charged pieces — $S^+$ and $S^-$, a fermion's $c^\dagger$ — are elements of the basis, but you never write one down: they appear only inside the neutral operators that physics asks for.

length(ops.S_z)
1

S_z is a single element of the basis, one letter. What the stock bases contain is chosen so that the operators one actually writes are atomic: a Heisenberg term under SU(2) is one letter on each site, and for the Hubbard site hubbard_basis(U1Irrep, SU2Irrep) the spinor $c^\dagger_\sigma$ is a single element, so a hopping term is one letter per site. Each basis is also complete: it spans every operator on its space, so products and H' never leave it.

Bsu2 = spin_basis(SU2Irrep)
S = spin_ops(SU2Irrep)
S.S_exchange       # S⃗ᵢ·S⃗ⱼ: one letter on each site, the vector operator
OpSum.LocalOperator{TensorKitSectors.SU2Irrep}(Terms(-2.598076211353318 + 0.0im * [sites=[1, 2], ops=OpSum.IrrepTensorOperators.IrrepOperator{TensorKitSectors.SU2Irrep}[ITO(Irrep[SU₂](1), n=1), ITO(Irrep[SU₂](1), n=1)], total=Irrep[SU₂](0)]), 2)

The symmetry decides what is neutral, and so what the builder offers: spin_ops(SU2Irrep) has only the rotation-invariant S_exchange, spin_ops(U1Irrep) has S_z, S_z_S_z, S_plus_S_min, S_min_S_plus and S_exchange, and spin_ops() (no symmetry) has the Cartesian components. spin_basis(sym; spin = 1) and the like select the spin; fermion_basis(U1Irrep) has number conservation, fermion_basis() only the parity (so that it also has the pairing f_plus_f_plus). A fermionic mode is graded by FermionParity ⊠ U1Irrep or FermionParity, and the braiding is what supplies the anticommutation signs.

Anything else: project

For any other single-site operator, write the TensorMap and project it into the basis:

Bc = spin_basis()                  # no symmetry
Vc = space(Bc)
σx = project(TensorMap(ComplexF64[0 1; 1 0], Vc ← Vc), Bc)
SiteOperator{TensorKitSectors.Trivial}(ITO(Trivial(), n=2) + ITO(Trivial(), n=3))

Both a plain V ← V and a charged V ← V ⊗ Vect[I](c => 1) are accepted, and a plain matrix (project(Xmat, B)) when there is no symmetry. The expansion is exact (the coefficients are inner products), and project re-materializes its own output and compares it against the input, throwing if the operator is outside the span of the basis (the stock bases are complete, so it never is). Nothing is converted to a dense Array, which matters for fermionic sectors.

The identity is element 1 of every basis, and a scalar multiple of it is scalarop; a placed identity is a pass-through, so it is dropped on placement and the term is shorter.

A basis of your own

Basis(ops) builds one from neutral operators, the identity implicit: a single-site operator is an element as it is, and a two-site one is factorised into its charged pieces. complete = true adds the matrix units it lacks, so that it spans everything.

Basis([ComplexF64[0 1; 1 0], ComplexF64[0 -im; im 0], ComplexF64[1 0; 0 -1]]; complete = true)
Basis(ℂ^2; 4 elements: Trivial() => 4)

An operator is atomic in a basis when it is one of its elements, and atomic operators are what keep the MPO small: the same Hamiltonian written in a poorer basis (for instance matrix units) has more letters per term and a larger bond dimension, so put the operators that appear in your Hamiltonian in the basis.

Placing and multiplying

A[i] places an on-site operator on site i and gives a one-term Terms bag; B[i, j] places a two-site LocalOperator on sites i and j; B[i] is contiguous (i:i+K-1). The sites may be in any order, and need not be adjacent: the sites in between are pass-throughs.

term = ops.S_plus_S_min[2, 5]
Terms(1.0 + 0.0im * [sites=[2, 5], ops=OpSum.IrrepTensorOperators.IrrepOperator{TensorKitSectors.U1Irrep}[ITO(Irrep[U₁](1), n=1), ITO(Irrep[U₁](-1), n=1)], total=Irrep[U₁](0)])

* between placed operators is the operator product, in the order written:

szz = ops.S_z[1] * ops.S_z[2]
szz ≈ ops.S_z_S_z[1, 2]
true

A few rules govern products and placement:

  1. Site order is free. A term is stored in site order, so an operand acting to the left of an earlier one has its leg inserted rather than appended, and the braiding phase that costs comes with it. For fermions that phase is the anticommutation sign, so $c^\dagger_{i+1} c_i$ is written as it reads (f_plus_f_min[i + 1, i]) and comes out as $-c_i c^\dagger_{i+1}$. Under a non-abelian symmetry the product is formed in the order written and re-coupled into site order with F- and R-symbols (computed by TensorKit, cached per term shape), so one term written out of order can become several.
  2. Products on a repeated site are products in the site's basis. a[i] * b[i] (or hop[i, i + 1] * hop[i + 1, i + 2], which share a site) is resolved when it enters an OperatorSum, expressed in the basis of that site; a bag holding such a product is not in normal form until then, so length and ≈ on it throw. Because the stock bases are complete the answer is always in the basis.
  3. Fermionic products carry the graded sign. Placing and multiplying two odd operators picks up the braiding of the legs that cross, which is the whole Jordan–Wigner bookkeeping, so there is no string to write.
  4. A product of charged operators needs a channel. * needs the totals of the factors to fuse to one sector, which neutral operators — all the builders return — always do.

The products that physics asks for are products of the neutral operators of the builder. A three-body term is a product of two bonds, and a four-body one a product of two:

ex = spin_ops(SU2Irrep).S_exchange
three = ex[1, 2] * ex[2, 3]          # (S₁·S₂)(S₂·S₃): the shared site is multiplied in the basis
four = ex[1, 3] * ex[2, 4]           # interleaved sites: re-coupled into site order
(typeof(three), typeof(four))
(OpSum.Terms{TensorKitSectors.SU2Irrep}, OpSum.Terms{TensorKitSectors.SU2Irrep})

Building blocks unplaced

A LocalOperator is the multi-site counterpart of a SiteOperator: the same term on K slots, placed later with B[i] or B[i, j]. Placement only relabels the sites, so it is exact for any symmetry (a fermionic hop across a gap carries its string), and the projection and its faithfulness check are paid once per block, not once per bond. LocalOperators add, subtract and scale, and B + α is a pass-through slot that placement drops:

b = spin_ops(SU2Irrep).S_exchange                         # K = 2, no site in sight
(b[2, 5] ≈ ex[2, 5], (b + 1 / 4)[1] ≈ ex[1, 2] + one(Terms{SU2Irrep}) / 4)
(true, true)

Placed and unplaced operands cannot be mixed in one call.

The hermitian-conjugate partner

H' on an OperatorSum builds it, so a hopping amplitude only has to be written once:

Bf = fermion_basis(U1Irrep)
F = fermion_ops(U1Irrep)
flat = FiniteChain(Bf, 2)
T = opsum(flat, -1.0 * F.f_plus_f_min[1, 2])
T + T' ≈ opsum(flat, -1.0 * (F.f_plus_f_min[1, 2] + F.f_plus_f_min[2, 1]))
true

The adjoint of a letter is a combination of the dual charge's letters, which only the basis knows, so ' lives on the container and a bare Terms bag has none (it throws, pointing here). It also works on an InfiniteChain. Every term must be charge-neutral, and an operator holding expterm channels has no adjoint.

Projecting a whole block

If you already have a $K$-site operator as a TensorMap — from a paper, an ED code, a kron — hand it to project together with the basis (or a list of bases, one per slot). It need not factorize into $A_i B_j$; a generic block works:

Bu = spin_basis(U1Irrep)
sz = ops.S_z_S_z
hbond = instantiate(
    opsum(
        FiniteChain(Bu, 2),
        (1 / 2) * ops.S_plus_S_min[1, 2] + (1 / 2) * ops.S_min_S_plus[1, 2] + sz[1, 2],
    )
)

Bxxz = project(hbond, Bu)
OpSum.LocalOperator{TensorKitSectors.U1Irrep}(Terms(1.0 + 0.0im * [sites=[1, 2], ops=OpSum.IrrepTensorOperators.IrrepOperator{TensorKitSectors.U1Irrep}[ITO(Irrep[U₁](0), n=2), ITO(Irrep[U₁](0), n=2)], total=Irrep[U₁](0)] + 0.5 + 0.0im * [sites=[1, 2], ops=OpSum.IrrepTensorOperators.IrrepOperator{TensorKitSectors.U1Irrep}[ITO(Irrep[U₁](1), n=1), ITO(Irrep[U₁](-1), n=1)], total=Irrep[U₁](0)] + 0.5 + 0.0im * [sites=[1, 2], ops=OpSum.IrrepTensorOperators.IrrepOperator{TensorKitSectors.U1Irrep}[ITO(Irrep[U₁](-1), n=1), ITO(Irrep[U₁](1), n=1)], total=Irrep[U₁](0)]), 2)

The result is a LocalOperator. Indexing places it (Bxxz[i], Bxxz[s₁, …, s_K]) and gives back a Terms bag:

sites = FiniteChain(Bu, 6)
Hxxz = opsum(sites, Bxxz[i] for i in 1:5)
length(Hxxz)
15

project(h, [B₁, B₂, …]) expands slot j in Bⱼ, which is how a block between different sites is written: the spin-½ / spin-1 exchange on the Lattices and geometry page is one.

Two accepted shapes, with K = numout(h):

h : V_1 ⊗ … ⊗ V_K  ←  V_1 ⊗ … ⊗ V_K                        # charge-neutral
h : V_1 ⊗ … ⊗ V_K  ←  V_1 ⊗ … ⊗ V_K ⊗ Vect[I](tot => 1)    # total charge tot

The physical spaces are read off h; atol/rtol control what counts as negligible.

A projected block is a sum of terms

The identity is the first element of every basis, so an on-site identity factor of a projected block is a pass-through, which placement drops: $\vec{S}_1 \cdot \vec{S}_2 + \tfrac{1}{4}$ projects into a two-site term plus a constant, and the constant takes no site.

Charged building blocks: couple

The neutral operators of the builders are enough for a Hamiltonian, and the charged elements of a basis are reachable when you need them: project(B[k], B) is the one-letter operator for the k-th element, a TensorMap of charge c, and couple fuses placed charged operators to a total charge, defaulting to the unit sector. This is the low-level term algebra underneath *, and the one place the fusion channels are visible:

Bs = spin_basis(SU2Irrep)
Sv = project(Bs[2], Bs)                     # the spin vector: the charge-1 element
couple_channels(Sv[1], Sv[2], Sv[3]; to = SU2Irrep(0))     # one tuple: nothing to name
1-element Vector{Tuple{TensorKitSectors.SU2Irrep}}:
 (1,)
chirality = couple(Sv[1], Sv[2], Sv[3])        # so the variadic form is unambiguous
Terms(1.0 + 0.0im * [sites=[1, 2, 3], ops=OpSum.IrrepTensorOperators.IrrepOperator{TensorKitSectors.SU2Irrep}[ITO(Irrep[SU₂](1), n=1), ITO(Irrep[SU₂](1), n=1), ITO(Irrep[SU₂](1), n=1)], total=Irrep[SU₂](0)])
  • couple(a, b; to = c) fuses two operands to total charge c; to defaults to the unit sector, and an unreachable to is an error rather than a silently empty result.
  • Every side may have several letters, and the coupling distributes over every combination; those whose charges cannot fuse to to are dropped.
  • Three or more operands: the variadic form takes every channel the charges force, and errors only where a channel is a genuine choice (several singlet channels for four spin-1 operators). Nest couple(couple(a, b; to = j₁₂), c; to = j) to name it; couple_channels lists the legal tuples.
  • Operands may be written in any site order; the legs are braided into place as for *.

Building the MPO

Ws[i] is the sparse bond matrix at site i and secs[i] lists the charge of each bond index to its right, so length(secs[i]) is the reduced bond dimension and sum(dim, secs[i]) the dense-equivalent one. irrep_mpo_tensors(W) assembles symmetric TensorMaps in the MPSKit leg convention $B_{i-1} \otimes V_i \leftarrow V_i \otimes B_i$.

The optional second argument selects the bond algorithm: BipartiteAlgorithm() (default, lossless minimum vertex cover) or SVDBondAlgorithm(trunc) with a MatrixAlgebraKit truncation strategy.

Where the lattice enters, and why there

Three tiers of the interface need progressively more of the lattice:

needswhat
site indices and charges onlycouple, dot, placement, Terms' opsum, canonicalize!, ≈
the site count N (or the cell period L)the whole sweep: mpo, mpo_terms
the spacesletter validation, H', instantiate, irrep_mpo_tensors

The container is where operators and sites are confronted: every letter is checked against its site's basis, and every term of a FiniteChain against 1:N, as the term is added:

try
    opsum(FiniteChain(Bu, 3), Bxxz[i] for i in 1:5)       # a term reaches past site 3
catch e
    println(sprint(showerror, e))
end
ArgumentError: a term acts on site 4, outside the lattice `1:3`

A lattice may be a FiniteChain, an InfiniteChain, or any iterable naming one Basis per site, which becomes a FiniteChain; a lattice of bare spaces is an error. FiniteChain(B, N) is the uniform chain, FiniteChain([B₁, B₂, …]) puts a different basis on every site. The natural shape for a model builder is to return the OperatorSum:

heisenberg(N; J = 1.0) = opsum(FiniteChain(Bsu2, N), J * S.S_exchange[i, i + 1] for i in 1:(N - 1))

mpo(heisenberg(64))

SVDBondAlgorithm has two truncation semantics, chosen by its sweep keyword, which agree exactly when trunc === nothing and differ once truncation bites:

sweepmeaning of truncrank(k)
IndependentSVD (default)k retained indices per bond — every bond is compressed on the raw prefix/suffix classes, independently of its neighbours
SequentialSVDk retained indices after upstream truncation — each bond is compressed in the basis the previous bond left behind, so an aggressive early truncation can starve the downstream bonds
mpo(H, SVDBondAlgorithm(truncrank(8)))                        # per-bond
mpo(H, SVDBondAlgorithm(truncrank(8); sweep = SequentialSVD)) # left-to-right sweep

A basis need not be orthogonal, so a truncating SVD compresses in the Hilbert–Schmidt inner product of each site's basis and writes the result back in it: the truncated operator depends on the span of the bases, not on how they were written. Without truncation the basis does not matter.

Jordan form, for an MPO library

irrep_mpo_tensors gives one dense TensorMap per site, with the whole bond collapsed into a single GradedSpace: right for checking a small chain, wrong for an MPO library, which wants the block structure back. jordan_mpo_tensors emits one BlockTensorKit.SparseBlockTensorMap per site, one level per bond index, with the bond indices reordered into upper-triangular (Jordan) form

⎛ 1  C  D ⎞     row/column 1   = "nothing placed yet"
⎜ ·  A  B ⎟     row/column end = "everything placed"
⎝ ·  ·  1 ⎠
Wsj = jordan_mpo_tensors(Hxxz)
map(W -> size(W, 4), Wsj)
6-element Vector{Int64}:
 5
 5
 5
 5
 5
 1

This is what MPSKit's JordanMPOTensor and FiniteMPOHamiltonian / InfiniteMPOHamiltonian consume; with MPSKit loaded (a weak dependency), instantiate(mpo(H)) builds them.

Both identity channels are emitted at every internal bond, even where the minimum vertex cover spent no index on them (nothing has finished at the first bonds, nothing starts after the last ones). The emitted MPO is minimal among Jordan-form MPOs and can exceed the cover's minimum (mpo(H).bondsectors) by at most two indices per bond: in practice +1 at the first and last internal bonds, 0 in the bulk. The padded channels are pure identity chains that cannot change the operator. The total charge must be trivial (a Jordan MPO's right boundary is an identity), and a truncation aggressive enough to empty a bond is rejected rather than silently emitted.

Operators that are not Hamiltonians

Nothing in the compression assumes a Hamiltonian, so the things you measure compress too, and by the same call. A total magnetisation opsum(lat, ops.S_z[i] for i in 1:N) is a pure one-site sum (D = 2), a two-point correlator ops.S_z[1] * ops.S_z[4] is a one-term MPO (D = 2), and a string order parameter is one term with a run of active sites.

The one place the two paths genuinely diverge is a charged operator — total charge other than unit(I), such as a bare $c^\dagger_2$, written as project(t, B)[2] for a TensorMap t with a charge leg. mpo and irrep_mpo_tensors handle it (the last bond is simply not the unit sector), but jordan_mpo_tensors refuses it, since a charged operator has no identity right boundary. The Jordan emission is for Hamiltonians handed to an MPS algorithm.

Infinite chains

Put the terms on an InfiniteChain and the same term algebra builds an infinite MPO with a repeating unit cell of L = length(chain) sites:

chain = InfiniteChain(Bu)            # one site per unit cell
Hgen = opsum(
    chain, 0.5 * ops.S_plus_S_min[1, 2] + 0.5 * ops.S_min_S_plus[1, 2] + ops.S_z[1] * ops.S_z[2]
)
Hinf = mpo(Hgen)
SymbolicMPO{TensorKitSectors.U1Irrep}(InfiniteChain, N = 1, D = [5])

The call has the same shape as the finite one; the result is a SymbolicMPO on the infinite chain.

The argument is a generating set, not the Hamiltonian: the operator represented is $\sum_{n \in \mathbb{Z}} \mathrm{translate}(H, nL)$, so each translation class must appear exactly once. Writing both ops.S_z_S_z[1, 2] and ops.S_z_S_z[2, 3] on a one-site cell would count the same class twice and is rejected by mpo; on a two-site cell they are different bonds and both are needed.

Hinf.bondsectors, Hinf.start, Hinf.finish
(Vector{TensorKitSectors.U1Irrep}[[0, 0, 1, -1, 0]], [1], [5])

It holds L bond matrices and bond-charge lists, with bond 0 identified with bond L, and carries the two boundary channels as bond indices: start[j] is the channel on which nothing has begun and finish[j] the one on which everything has finished. irrep_mpo_tensors(Hinf) assembles L site tensors that tile.

Note

Terms must be charge-neutral, and SVDBondAlgorithm is not available here: it compresses each bond independently against a vacuum-terminated layout, with no bond basis that closes on itself. Terms with no support (K = 0) are rejected too, since Σ_n c·𝟙 does not converge.

Exponentially decaying interactions

A term sum can only hold couplings of finite range. expterm adds the one infinite-range family an MPO represents exactly at fixed cost — a geometric decay, which is a scalar λ on the diagonal of a bond channel:

\[\sum_{i<j} \lambda^{\,j-i-1}\, A_i\, S_{i+1}\cdots S_{j-1}\, B_j ,\qquad 0 < |\lambda| < 1 .\]

You write one representative term and say where the stretched gap is; everything else — the charges, the caterpillar fusion tree — comes from that term, exactly as for a finite-range coupling:

Hexp = opsum(
    chain,
    0.5 * ops.S_plus_S_min[1, 2] + 0.5 * ops.S_min_S_plus[1, 2],              # nearest neighbour
    expterm(ops.S_z_S_z[1, 2]; decay = 0.6),                                  # + geometric Sᶻ tail
)                                                # or a FiniteChain
Hgeo = mpo(Hexp)
Hgeo.bondsectors
1-element Vector{Vector{TensorKitSectors.U1Irrep}}:
 [0, 1, -1, 0, 0]

The expterm channels live in the same OperatorSum as the finite-range terms, so all four finite/infinite × plain/decaying cases use mpo(H). The lattice fixes the translation period: on an L-site cell the entry and the exit both step by L (and, as above, H is a generating set), while on a FiniteChain every site is a possible entry and the operator represented is the geometric sum truncated to the chain — OpSum.chain_terms(H) writes it out.

  • decay counts per site of the string, so the shortest translate carries λ to the power of the representative's own gap and every further period costs λ^L. |λ| ≥ 1 is rejected.
  • exitsite (default: the representative's last site) is the first site of the exit block. Sites before it form the entry block, so multi-site blocks on either end work: expterm(ops.S_z_S_z[1, 2] * ops.S_z[4]; decay = λ, exitsite = 4).
  • string is an on-site operator carried by the stretched gap (default: the identity), projected into the sites' basis like any other operator (string = project(P, B)). It must be charge-neutral — a charged string would make the running bond charge drift along the loop. A channel's letters land on sites it does not name — its translates move by one site on a finite chain, and a string fills every site of the gap — so those sites must all carry the same basis; on an InfiniteChain with a mixed cell, a channel without a string is fine.
  • A sum of exponentials is a sum of expterms. Channels with different λ are linearly independent, so each costs one bond index; channels sharing (λ, string, exit) merge into one.
Note

A channel's period is part of its declaration, so writing the same interaction on a larger unit cell is not free: on an L-site cell an all-pairs geometric coupling needs L² channels and costs L bond channels instead of one. Write the smallest cell you can. Jordan blocks (polynomial × exponential) and power-law fitting are not supported; research/infinite-mpo.md §7 is the design note.

Recommended patterns

Hand every term to opsum at once. opsum(lat, terms...) makes one pass over each argument and iterables nest, so building an M-term Hamiltonian is $\Theta(M)$ (32640 terms on 256 sites take a few hundredths of a second) and several families of terms need no vcat:

ex = spin_ops(SU2Irrep).S_exchange
h = opsum(
    lat,
    (J1 * ex[i, j] for (i, j) in nn_bonds),
    (J2 * ex[i, j] for (i, j) in nnn_bonds),
)

append!(h, terms) (and opsum!(H, terms...) on an OperatorSum) is likewise one pass but mutates, so start from something you own (zero(h), Terms{I}(), OperatorSum(lat), copy(h)). + copies the accumulated list, so folding it (for t in terms; H = H + t; end) is quadratic: fine for a handful of terms, wrong for thousands. The normal form (coincident terms summed, cancelled ones dropped) is taken once, by canonicalize!, when the term set is first observed or compressed, so length(H) is the number of terms the operator has, never the number appended.

Project a bond block once, place it per bond. project(h, B) and the two-site builder entries are unplaced LocalOperators, so a translation-invariant chain is opsum(lat, Bxxz[i] for i in 1:(N - 1)) with a single projection however long the chain. The stock bases and builders are memoised per symmetry, so calling them inside a term loop is cheap.

Order the sites of a 2D lattice so bonds stay short. An MPO lives on a chain. Column-major ordering $(x, y) \mapsto (x-1)L_y + y$ keeps every bond of a cylinder within $L_y$ sites, which makes the bond dimension linear in the circumference and independent of the length.

Pick the largest symmetry you can express, and put the operators you use in the basis. The same Heisenberg chain needs 3 reduced bond indices under SU(2) and 5 under U(1); the reduced number is what a DMRG sweep pays for.

Verifying an operator

Three checks, in increasing cost:

# 1. Faithfulness — cheap, symbolic, valid at any N and for any sector including fermionic.
#    `islossless` does the reconstruct-and-compare in one call: `≈` on two term bags compares the
#    canonical term sets exactly and the coefficients approximately.
islossless(Hxxz)
true
# 2. Tensor assembly — contract the MPO with `mpo_tensormap` and compare against the dense oracle.
#    Exponential in N, but it stays inside TensorKit, so it is valid for fermions too.
mpo_tensormap(irrep_mpo_tensors(W)) ≈ instantiate(Hxxz)
true
  1. Spectrum — the physics check, and the only honest route for fermions against an external reference. Diagonalize instantiate(H) block by block, repeating each eigenvalue dim(c) times so spectra are comparable across symmetry groups. examples/common.jl has a spectrum helper; a hermiticity_error check is the sharpest detector of a wrong fermionic sign.

Note that check 1 says nothing after a truncating SVDBondAlgorithm — it assumes lossless compression.
