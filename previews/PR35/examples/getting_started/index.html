Getting started

One bond, then one Hamiltonian, with every step named. Every later page adds exactly one thing to what is here.

The pipeline has three objects and they stay separate on purpose:

  1. a term bag — what you write down. It knows site indices and charges, and no lattice.
  2. a lattice — one physical space per site. Supplied where the MPO is formed, not where the terms are written, because that is the first place the spaces are actually needed.
  3. an MPO — the compressed result.
using OpSum: OpSum
include(joinpath(pkgdir(OpSum), "examples", "common.jl"))
hermiticity_error (generic function with 1 method)

One bond

spin(V) is the single irreducible tensor operator of an SU(2) site — the vector operator $\vec{S}$ itself, not three separate components. S[i] places it on site i, and dot couples two placements to a scalar.

V = SU2Space(1 // 2 => 1)
S = spin(V)
h = dot(S[1], S[2])
Terms(-2.5980762113533156 + 0.0im * [sites=[1, 2], ops=OpSum.IrrepTensorOperators.IrrepOperator{TensorKitSectors.SU2Irrep}[ITO(Irrep[SU₂](1), n=1), ITO(Irrep[SU₂](1), n=1)], total=Irrep[SU₂](0)])

That is already a Terms: a bag of terms, and the compressible operator. It carries no lattice, so it does not yet know what a "site" is physically — only that there are two of them and which charges they carry.

lat = FiniteChain(V, 2)
mpo = irrep_mpo(h, lat)
FiniteMPO{TensorKitSectors.SU2Irrep}(N = 2, D = [3, 1])

The MPO destructures as the pair it holds, on either lattice:

Ws, secs = mpo
length(secs)
2

Three ways to check it

In increasing cost, and every later page uses at least the first.

Faithfulness. Reconstruct the term bag from the bond data and compare. This is purely symbolic, needs no lattice at all — the bond data names charges but not spaces — and works at any N and for any sector, fermions included.

islossless(h, lat)
true

Equivalently, spelled out: mpo_terms is the inverse of the compression.

mpo_terms(Ws, secs) ≈ h
true

The assembled tensors. Build the symmetric TensorMaps, contract the chain, and compare against the dense oracle. Exponential in N, so small systems only, but it never leaves TensorKit and so is valid for fermionic sectors too.

mpo_matches_oracle(h, lat)
true

The spectrum. The physics check, and the only honest one against an external reference. A single SU(2) bond has the singlet/triplet split $-3/4$ and $1/4$:

spectrum(h, lat)
4-element Vector{Float64}:
 -0.75
  0.2499999999999998
  0.2499999999999998
  0.2499999999999998

A Hamiltonian

opsum accumulates any number of arguments in one pass, and iterables nest. + also works, but it copies, so folding it over many terms is quadratic — opsum (or append! into a bag you own) is the linear route.

heisenberg(N; J = 1.0) = opsum(J * dot(S[i], S[i + 1]) for i in 1:(N - 1))

No symmetry at all: transverse-field Ising

ℂ^2 is an ungraded space, so there is nothing to exploit and the Pauli matrices are simply written down. project expands a TensorMap in the on-site alphabet, which is how every on-site operator in these pages is built — never by writing a letter index by hand, because those follow TensorKit's block order and hard-coding one is a silent bug.

Vc = ℂ^2
σx = project(TensorMap(ComplexF64[0 1; 1 0], Vc ← Vc), Vc)
σz = project(TensorMap(ComplexF64[1 0; 0 -1], Vc ← Vc), Vc)
SiteOperator{TensorKitSectors.Trivial}(ITO(Trivial(), n=1) + -1.0 + 0.0im*ITO(Trivial(), n=4))

This model also mixes arities: the field is a one-site term and the coupling a two-site one, in one operator. Nothing special is needed for that — opsum takes both.

function tfim(N; J = 1.0, g = 0.5)
    return opsum(
        (-J * couple(σz[i], σz[i + 1]) for i in 1:(N - 1)),
        (-g * σx[i] for i in 1:N),
    )
end

Htfim = tfim(6)
build("TFIM N=6", Htfim, FiniteChain(Vc, 6))
islossless(Htfim, FiniteChain(Vc, 6))
true

At $g = J$ the chain is critical; away from it the gap opens. The ground-state energy is the first entry of the spectrum:

for g in (0.0, 0.5, 1.0, 2.0)
    E = spectrum(tfim(6; g), FiniteChain(Vc, 6))[1]
    println("  g=$g  E₀=", round(E; digits = 6))
end

An abelian symmetry: XXZ

Grade the site by magnetisation and U(1) is available. matrixunit(V, out, in) is $|out⟩⟨in|$, which is all the spin operators are:

Vu = Rep[U₁](0 => 1, 1 => 1)
up, dn = U1Irrep(1), U1Irrep(0)
Sp = matrixunit(Vu, up, dn)
Sm = matrixunit(Vu, dn, up)
Sz = (matrixunit(Vu, up, up) - matrixunit(Vu, dn, dn)) / 2
SiteOperator{TensorKitSectors.U1Irrep}(0.5 + 0.0im*ITO(Irrep[U₁](0), n=2) + -0.5 - 0.0im*ITO(Irrep[U₁](0), n=1))

Sᶻ is worth a second look: it is a composite on-site operator, two alphabet letters with coefficients, and ordinary arithmetic on SiteOperators reads the way you would write it on paper. couple distributes over both operands, so nothing has to be expanded by hand.

length(Sz)
2

spin_ops bundles exactly these three. Its sectors argument is in descending magnetisation, and is not optional: a Vect[U₁] spin site is as often labelled by particle number as by $m$, and inferring which would be a silent guess.

spin_ops(Vu, up, dn).Sz ≈ Sz
true

\[H = \sum_i \tfrac12 \left( S^+_i S^-_{i+1} + S^-_i S^+_{i+1} \right) + \Delta\, S^z_i S^z_{i+1}\]

function xxz(N; Δ = 1.0)
    return opsum(
        couple(Sp[i], Sm[i + 1]) / 2 + couple(Sm[i], Sp[i + 1]) / 2 +
            Δ * couple(Sz[i], Sz[i + 1]) for i in 1:(N - 1)
    )
end

At $Δ = 1$ this is the Heisenberg chain, just graded by U(1) instead of SU(2) — same operator, two symmetries. The MPOs are not comparable (different spaces, different bond labels), but the spectra are, once multiplet degeneracies are unfolded:

spectrum(Hxxz, FiniteChain(Vu, 6)) ≈ spectrum(heisenberg(6), FiniteChain(V, 6))
true

And this is the payoff of the symmetry, in one line: the same operator costs a smaller bond dimension under the larger group.

let N = 6
    u1 = build("XXZ (U(1))", xxz(N), FiniteChain(Vu, N); quiet = true)
    su2 = build("Heisenberg (SU(2))", heisenberg(N), FiniteChain(V, N); quiet = true)
    println("  U(1):   D=$(u1.D)  D_dense=$(u1.Ddense)")
    println("  SU(2):  D=$(su2.D)  D_dense=$(su2.Ddense)")
end
  U(1):   D=6  D_dense=6
  SU(2):  D=3  D_dense=5
